# Phase 2D — 휴대폰 단체 사진 출석

[English guide](phase2d-mobile-photo-attendance.md)

브랜치: `DoJun/phase2d-mobile-photo-attendance`. 2C 커밋 `6be4117`에서 시작했습니다.

## 바뀐 기능과 테스트 순서

1. 교사 로그인 후 모바일 하단 **Capture → Attendance photo → 수업·날짜 선택 → Continue to camera**로 바로 촬영을 시작합니다. 기존 **Feedback photo**는 학생 리포트 피드백용 촬영을 유지합니다. 데스크톱에서는 **Attendance → 수업 상세 → Photo attendance · teacher review**로 들어갑니다.
2. 촬영 방법을 선택합니다.
   - **Open camera**: 웹 안에서 촬영합니다. 교사는 후면 카메라를 우선 요청하고, 노트북에서는 Front / laptop camera를 선택할 수 있습니다. 요청한 방향이 없으면 다른 카메라를 쓸 수 있으므로 미리보기를 확인합니다.
   - **Use phone camera**: 휴대폰 기본 촬영 기능을 요청하는 파일 입력입니다. 기기에 따라 파일 선택 창이 나올 수도 있습니다.
   - **Choose saved photo**: 저장된 JPEG/PNG를 선택합니다.
3. 웹 카메라에서 촬영 대상자의 동의를 확인하고 **Take photo**를 누릅니다. 카메라가 꺼지고 촬영 사진을 보여줍니다. **이 시점에는 서버로 사진을 보내지 않습니다.**
4. 흐리거나 얼굴이 잘렸으면 **Retake photo**로 다시 찍습니다. 새 촬영에는 동의를 다시 확인합니다. 괜찮으면 **Use photo and recognize**를 누릅니다. 닫으려면 **Close camera**를 누릅니다.
5. 인식 결과에서 사진 속 얼굴 번호 또는 아래 번호 버튼을 누릅니다. 해당 얼굴을 확대한 이미지와 학생 후보를 한 번에 한 얼굴씩 보여줍니다.
6. 사진을 확인하고 학생을 선택합니다. 이미 다른 얼굴에 선택한 학생은 다시 선택할 수 없습니다. 잘못 선택했다면 먼저 기존 얼굴에서 선택을 바꿉니다. 지각이면 **Mark this student late**를 체크합니다.
7. **Next face** 또는 **Next unreviewed**로 이동합니다. 학생을 확실히 구별할 수 없으면 **Exclude / cannot identify**를 선택합니다. 상단에 검토 완료·학생 선택·제외·남은 얼굴 수가 표시됩니다.
8. 모든 얼굴의 선택 또는 제외를 완료한 뒤 교사 확인 체크박스를 체크하고 **Confirm and save attendance**로 저장합니다. 후보 선택만으로 출석이 저장되지는 않습니다.
9. 얼굴이 없거나 인식이 어려운 학생은 **Open manual attendance**를 눌러 출석 표로 이동하고 **Manual / Correct**로 수동 처리합니다. 제외·미검출 학생을 자동 결석 처리하지 않습니다.

사진 검토 도중 수동 출석을 변경하면 기존 서버의 충돌 검사가 작동할 수 있습니다. 그때는 이미 저장된 출석을 확인하고 사진 검토를 새로 시작합니다. 학생 본인의 출석 요청은 기존 전면 카메라와 **Capture and request attendance** 흐름을 유지합니다.

Capture에서 취소된 수업은 선택할 수 없습니다. 출석 촬영 창을 닫으면 저장하지 않은 사진과 선택이 사라지고 카메라가 꺼집니다. 이미 서버로 전송한 저장 요청은 완료될 수 있습니다. **Close camera → Open manual attendance**로 선택한 수업의 수동 출석 화면으로 이동할 수 있습니다. 사진 출석 기능이 꺼져 있으면 수동 출석을 안내합니다.

Chrome 개발자 도구의 기기 모드에서 폭을 390px 정도로 설정하면 하단 Capture를 테스트할 수 있습니다. 이때 촬영에는 노트북 웹캠을 사용하며, **Front / laptop camera**를 선택하면 됩니다.

## 지금 실행하는 방법

현재 노트북에서는 [로컬 화면](http://localhost:5173)을 새로고침하면 됩니다. 이번 변경은 프론트엔드이며 DB 초기화·마이그레이션·모델 재설치는 없습니다. 시작·종료 명령도 같습니다.

```powershell
# 저장소 루트에서 실행
powershell -ExecutionPolicy Bypass -File .\data\local-dev\start.ps1
powershell -ExecutionPolicy Bypass -File .\data\local-dev\stop.ps1
```

위 스크립트는 현재 PC의 Git 제외 로컬 설정입니다.

**실제 휴대폰 접속 환경은 별도 준비가 필요합니다.** 휴대폰에서 `localhost:5173`을 열면 노트북이 아니라 휴대폰 자신을 가리킵니다. 현재 로컬 서버를 외부에 공개하거나 방화벽을 변경하지 않았습니다. 휴대폰 테스트에는 휴대폰에서 접근 가능한 신뢰된 HTTPS 주소와 동일 출처 API·로그인 설정을 준비해야 합니다.

웹 안에서 카메라를 켜는 기능에는 HTTPS 또는 localhost 같은 보안 컨텍스트가 필요합니다. 노트북 IP를 단순 HTTP 주소로 여는 것만으로는 동일하게 동작하지 않습니다. [MDN 카메라 접근 설명](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia). 기본 촬영 앱을 여는 `capture` 기능도 브라우저·기기별 지원 차이가 있습니다. [MDN capture 설명](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture).

## 실패했을 때

- 카메라 권한 거부: 권한을 허용한 후 **Retry camera**. 어려우면 닫고 사진 파일을 선택합니다.
- 사진이 흐리거나 얼굴이 작음: 더 가까이, 밝은 환경에서 작은 그룹으로 나누어 촬영합니다.
- HEIC 파일: 기존처럼 지원하지 않습니다. JPEG/PNG를 사용합니다. 파일은 20 MB 이하·25메가픽셀 이하로 준비합니다.
- 인식 서버 오류: 준비된 사진을 유지하므로 **Recognize faces**로 재시도할 수 있습니다. 동일 사진에는 기존 요청 키를 재사용합니다.
- 검토 만료: 사진을 다시 촬영하거나 수동 출석을 사용합니다.
- 잘못된 후보: 강제로 후보를 선택하지 말고, 확실히 신원을 확인할 수 있을 때만 학생을 지정합니다. 그렇지 않으면 제외합니다.

웹 촬영은 가로 1920·세로 1440 범위 안에서 원래 비율을 유지합니다. 파일 업로드는 기존 방향 보정·메타데이터 제거·크기 제한을 재사용합니다. 최대 30얼굴은 서비스의 처리 상한이며, 30명 단체 사진의 정확도를 보장한다는 뜻은 아닙니다.

## 데이터와 구현 범위

촬영 미리보기와 확대 얼굴은 브라우저 메모리에서 사용합니다. 확대 얼굴은 원본의 일부를 화면에 그린 것이며 서버에 별도 업로드하지 않습니다. 닫기·재촬영·화면 이동으로 로컬 촬영 상태를 정리하며, 저장 완료·검토 만료 시 준비된 사진을 비웁니다. 브라우저 저장소에 사진을 추가하거나 자동 다운로드하지 않습니다.

카메라 전환·닫기·촬영·화면 이동 시 스트림을 해제하고, 재생 오류가 난 경우에도 이미 획득한 카메라를 해제하도록 보완했습니다. 다른 수업으로 이동한 후 늦게 도착한 인식·저장 응답은 현재 화면에 반영하지 않습니다. 이미 전송된 서버 요청은 완료될 수 있습니다.

기존 인증·동의·교사 승인·명단 변경·만료·중복 저장 검증을 유지합니다. 서버 API, DB, 모델, 인식 임계값과 의존성은 변경하지 않았습니다.

주요 파일: `RecognitionCamera.tsx`, 새 `PhotoFaceReview.tsx`, `SessionPhotoPanel.tsx`, `SessionDetail.tsx`, `useCameraCapture.ts`, `photoAttendance.css`. 하단 Capture 연결은 `MobileConsoleChrome.tsx`, 새 `AttendanceCaptureDialog.tsx`, `TeacherApp.tsx`, `mobile-teacher.css`에서 처리합니다.

## 검증 결과와 남은 확인

- 프론트엔드 빌드 및 테스트 346개 통과.
- Chrome 390×844에서 Capture 용도 선택, 수업 선택 필수·취소된 수업 제외, 촬영 미전송·닫기·재진입, 기존 피드백 파일 콜백, 사진 출석 비활성 시 수동 출석 안내, 수업 없음 안내를 확인했습니다. 실제 React 컴포넌트와 가상 수업/API를 사용했으며 JavaScript 오류는 없었습니다.
- 새 회귀 테스트: 카메라 전환·늦은 권한 응답 정리, 재생 실패 후 스트림 해제·재시도, 세로 사진 비율, 미리보기 준비 전 촬영 차단.
- 1440×1000 및 390×1000 Chrome/Playwright: 촬영 전 동의, 사진 확인 전 미전송, 재촬영, 카메라 전환·닫기, 3얼굴 검토·중복 선택 차단·지각·제외·최종 저장, 30얼굴 탐색, 오류 재시도·만료·미검출·학생 촬영 회귀 검증.
- 가상 API로 여러 학생을 구성했습니다. 생체인식 정확도 검증은 아닙니다. 의미 없는 빈 화면·프레임워크 오류 화면·JavaScript 오류·가로 넘침은 없었습니다.
- 실제 로컬 서버에서 로그인 후 수업 조회, 카메라 미리보기·촬영·취소, 수동 출석 표 연결을 확인했습니다. 이 실서버 확인 과정에서 사진을 업로드하거나 사용자 출석을 변경하지 않았습니다.
- Browser 플러그인이 없어 기존 Playwright 환경을 사용했습니다. 임시 스크립트와 화면 캡처는 저장소 밖에 보관했습니다.

실제 Android/iPhone의 후면 카메라 선택·기본 촬영 앱·Safari·폰 사진의 방향 보정과 동의한 여러 사람의 인식 정확도는 아직 직접 테스트해야 합니다. 이번 모바일 크기 테스트는 실물 휴대폰 테스트를 대체하지 않습니다.
