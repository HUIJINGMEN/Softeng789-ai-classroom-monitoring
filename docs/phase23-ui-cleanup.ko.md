# Phase2·3 화면 정리 검토 기록

검증일: 2026-10-30 (Pacific/Auckland).

## 기준과 현재 상태

- 시작 시 작업 트리는 깨끗했고 HEAD는 통합 커밋 `fce61cf`였습니다.
- `DoJun/phase2-3-ui-cleanup` 브랜치를 생성했습니다. 동일 폴더의 다른 채팅은 작업 중이 아니었습니다.
- 구현 내용은 미커밋 상태입니다. 커밋·push·배포는 사용자 검토 후 별도 지시를 받아 진행합니다.

## 화면 변경

1. **학생 홈·출석**: 오늘 수업과 저장된 출석 상태를 우선 표시합니다. 날짜는 Auckland 기준입니다. 인접 날짜 수업과 기존 학습 기록·업데이트는 펼쳐서 확인합니다. `Open camera & activity`와 `Full schedule`을 홈 상단에 배치하고, `Camera & activity`를 데스크톱 상단 메뉴와 모바일 하단의 독립 탭으로 추가했습니다. 사진 출석 동의·철회 관리는 `Profile`로 이동했고, 등록이 필요한 경우에만 홈에 안내합니다. 사진 출석 기능이 비활성인 경우에도 일정과 수동 출석 안내를 표시합니다.
2. **카메라**: 별도 화면에서 미리보기·시작/정지·로컬 동의·두 공유 스위치·공유 상태를 표시합니다. 현재 얼굴 감지 상태·참조 설정 버튼·최근 관찰 기록은 기본으로 표시합니다. 상세 수치·설정 안내·Phase3D 실험만 접어 두었습니다. 카메라 정지 시 로컬 동의와 성인 확인도 초기화합니다. 화면을 나가면 카메라와 공유를 정리합니다.
3. **교사 목록**: 학생 목록을 기본 화면으로 표시합니다. 출석 상태와 관찰 공유 상태를 구분합니다. 학생 상세를 열면 관찰 요약과 해당 학생의 영상 보기 버튼을 표시하며, 상세를 닫으면 영상 수신을 해제합니다. 기존 검색·필터·20명 단위 페이지 이동·관찰 검토 기능을 유지합니다. 관찰 공유가 비활성인 환경에서도 사용할 수 있도록 `Shared videos only` 진입을 유지했습니다.

UI 문구는 영어입니다. 기존 학습 기록·결제·보고서 등의 화면은 유지합니다.

## 유지한 경계

- 사진 출석 요청과 교사의 실제 출석 저장을 구분합니다. 저장된 출석이 과거 요청 상태보다 우선합니다.
- 사진 제출 동의, 로컬 분석 동의, 관찰 공유 동의, 영상 공유 동의를 별도로 유지합니다.
- 관찰 공유 중지/삭제는 영상 공유를 중단하지 않고, 영상 공유 중지도 관찰 공유와 원본 카메라를 중단하지 않습니다.
- Phase3D 감지 알고리즘·임계값·워커·카메라 분석 코드는 변경하지 않았습니다. `LocalEyeHeadPanel.tsx`도 원본 그대로이며 외부 표시 영역만 접었습니다.
- Phase3D 결과를 교사에게 전송하거나 출석·집중도·졸음 점수로 연결하지 않았습니다.
- 영상 공유 한도는 최대 4명으로 유지합니다. 21명 목록 검증은 영상 동시 부하 검증이 아닙니다.
- 백엔드·Python 서비스·DB 스키마는 변경하지 않았습니다. 사용자 얼굴·출석 데이터를 초기화하거나 수정하지 않았습니다.

## 검증 결과

### 카메라 기능 구역 정리 추가 검증 (2026-11-02)

- `Camera & activity` 내부를 Camera & detection / Recent observations / Share with your teacher / Experimental tools 카드로 구분했습니다. 상단 구역 바로가기를 제공하며, 데스크톱에서는 카메라와 기록을 나란히, 모바일에서는 세로로 배치합니다.
- 카메라 카드 안에 동의·시작/중지·참조 설정을 모으고, 관찰 카드에는 현재 감지·세션 기록·빈 상태를 표시합니다. 교사 공유의 두 동의는 각각 유지합니다. 상태 처리와 감지 알고리즘은 변경하지 않았습니다.
- 현재 작업 트리의 프론트엔드 테스트 412개와 TypeScript/Vite 빌드가 통과했습니다. 이 개수에는 별도 작업에서 추가된 회원가입 테스트도 포함됩니다.
- 로컬 Chrome/Playwright에서 320·390·820·1024·1321·1440px의 가로 넘침 없음, 네 카드와 바로가기, 키보드 메뉴 진입을 확인했습니다. 가상 카메라의 실제 MediaPipe 얼굴 미감지 기록, 화면 이탈 시 카메라 종료도 통과했습니다.
- 모의 공유 API로 두 동의의 독립 전환, 관찰 삭제 시 영상 유지, 중지/재시작 시 초기화를 확인했습니다. 실제 공유 데이터는 변경하지 않았습니다.
- 브라우저 런타임 예외와 프레임워크 오류 화면은 없었습니다. 콘솔의 `/favicon.ico` 404는 별도로 확인했으며 이번 작업에서 해당 파일은 변경하지 않았습니다.
- Browser 플러그인이 제공되지 않아 기존 Playwright 환경을 사용했습니다. 검증 스크립트와 캡처는 저장소 밖 `C:/Users/ASUS/.codex/visualizations/2026/10/29/01a18843-4ada-7330-9411-0278b020721b/camera-sections/`에 있습니다. 실제 휴대폰·실제 얼굴·장치 간 영상 전송 검증 한계는 아래와 동일합니다.

## 검증 한계

사용자 검토 후 카메라 진입을 독립 메뉴로 바꿨습니다. 추가 검증에서 320·390·820·1024·1321·1440px의 메뉴 겹침/잘림 없음, Enter 키 진입, 현재 탭 표시, 가상 카메라의 실제 MediaPipe `No face detected` 기록 기본 노출, 다른 탭으로 이동 시 카메라 트랙 종료를 확인했습니다. 해당 변경 후에도 407개 테스트와 타입 검사·빌드가 통과했습니다. 추가 검증 스크립트는 `data/phase23-ui-cleanup-qa/camera-tab-smoke.mjs`, 화면 캡처는 `output/playwright/student-camera-tab-mobile.png`와 `student-observations-visible-mobile.png`입니다.

- 모바일 검증은 데스크톱 Chrome의 화면 크기 에뮬레이션입니다. 실제 휴대폰 카메라·HTTPS 환경은 검증하지 않았습니다.
- 얼굴 없는 가상 카메라를 사용했습니다. 실제 얼굴 정확도나 새 사진 요청 → 교사 승인 → DB 출석 저장 전 과정을 이번에 다시 검증한 것은 아닙니다. 출석 상태/제출 추가 검증은 모의 응답 기반입니다.
- 서로 다른 장치/네트워크 간 실시간 영상 전송과 다중 영상 부하는 재검증하지 않았습니다.
- 백엔드와 Python이 변경되지 않아 이번 UI 작업에서는 해당 전체 테스트를 재실행하지 않았습니다. 이전 통합 검증 결과와 환경 한계는 [통합 인계 문서](phase23-integration-handoff.ko.md)에 있습니다.
