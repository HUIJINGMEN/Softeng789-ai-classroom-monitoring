# 2B — 촬영 직후 얼굴·품질 검사

작업 브랜치: `DoJun/phase2b-capture-validation` (`02388e6`에서 분기).

## 사용 방법

1. 학생 가입에서 얼굴 출석을 선택하고 성인·동의 항목을 확인합니다.
2. **Capture pose**를 누르면 **Checking photo…**가 표시됩니다.
3. 검사에 통과하면 사진이 목록에 추가되고 다음 자세로 넘어갑니다.
4. 실패하면 현재 단계에서 이유와 실패한 사진이 표시됩니다. 안내에 맞게 조정하고 **Capture pose**를 다시 누릅니다.
5. 7장 완료 후 제출합니다. 서버가 전체 품질과 동일인 여부를 다시 검사하고, 기존처럼 관리자 승인을 기다립니다.

교사의 얼굴 등록 화면에도 동일하게 적용합니다. **Retake 번호**로 한 장만 교체할 수 있고, 교체 사진이 실패하면 기존 사진과 나머지 사진은 유지됩니다. **Cancel retake**는 기존 사진을 유지한 채 재촬영을 취소합니다. 검사 중 중복 촬영은 막고, 재촬영 취소·전체 초기화·동의 철회·화면 이동 뒤 늦게 도착한 응답은 무시합니다.

## 무엇을 검사하나요?

얼굴이 정확히 한 명인지, 얼굴이 너무 작거나 흐리지 않은지, 너무 어둡거나 밝지 않은지 검사합니다. 기존 모델과 기준을 유지합니다. **오른쪽을 정확히 바라봤는지, 실제 살아 있는 사람인지, 본인인지 확인하는 검사는 아닙니다.** 동일인 비교는 최종 7장 제출에서 수행합니다. 검사 즉시 피드백을 주는 개선이며 얼굴 검출 정확도가 높아졌다는 뜻은 아닙니다.

각 사진은 동의 후 서버로 전송되지만 사전 검사에서 계정·사진·얼굴 특징·출석 기록을 저장하지 않습니다. 실패 미리보기는 브라우저 메모리에만 유지됩니다. 일반적인 파일 업로드 처리 중 임시 파일은 사용될 수 있습니다. 최종 제출 후 저장·보관·승인 정책은 기존과 같습니다. 얼굴 없는 수동 가입과 수동 출석도 유지됩니다.

## 오류와 재시도

- `No face`: 거의 정면에 가깝게, 두 눈이 보이도록 촬영합니다.
- 여러 얼굴: 본인만 화면에 들어오게 합니다.
- 얼굴 작음·흐림·조명: 가까이 앉아 움직임을 멈추고 앞쪽 조명을 사용합니다.
- 서버 사용 중 또는 요청 제한: 잠시 기다렸다가 재시도합니다. 요청 제한 메시지가 나오면 1분 후 다시 시도합니다.
- 네트워크 오류·25초 제한: 사진은 통과 처리하지 않습니다. 다시 촬영하거나 수동 출석을 선택합니다.

시작·종료 명령어는 기존과 같습니다. 이 브랜치로 변경한 뒤 백엔드와 Python 서버를 재시작해야 합니다. DB 전환이나 데이터 초기화는 필요하지 않습니다. 실제 본인 얼굴과 다른 동의한 사람·기기로 추가 확인해야 합니다.

API, 요청 제한과 테스트 기준은 [영문 가이드](phase2b-capture-validation.md)를 참고하세요.

검증 결과: Python 14개, Java 가입·권한 16개와 검사 계약·요청 제한 2개, 실제 Python 연결 gateway 4개가 통과했습니다. 기존 프론트엔드 333개와 새 취소·타임아웃 회귀 테스트 3개 및 빌드도 통과했습니다. 데스크톱/모바일 합성 카메라 화면 검증과 실제 서버의 얼굴 없는 사진 거절까지 확인했습니다. 이후 사용자가 직접 테스트하여 정상 동작을 확인하고 본인 fork에 커밋·push를 요청했습니다. 여러 사람의 얼굴 통과율과 미등록 얼굴 오인식 여부는 별도 테스트가 필요합니다.
