# Phase 4A 입구 출석 키오스크 가이드

교사나 관리자가 교실 입구의 브라우저 하나를 **한 수업 세션 전용 얼굴 출석 키오스크**로 바꾸는 기능입니다. 학생이 카메라 앞에 서면 Phase 1 CPU 인식기가 그 수업 학생 중에서 이름을 최대 3개 제안하고, 학생이 자기 이름을 직접 고릅니다. 출석은 이 확인이 있을 때만 출처 `KIOSK`로 기록됩니다. 인식 결과만으로는 출석이 기록되지 않습니다.

학생이 1순위가 아닌 이름을 고르거나 수강 등록이 안 된 학생이 확인하려고 하면, 그 시도는 관리자 검토 목록에 올라가고 사진이 30일 동안 보관됩니다.

**Phase 1–2와 다른 정책**
- 사진 출석과 학생 체크인에서는 AI가 관여한 출석을 모두 교사가 확정합니다.
- 키오스크는 교사가 명시적으로 시작하는 별도 정책입니다. 수업 권한이 있는 교사가 한 세션에 키오스크 하나를 허가하고, 각 기록은 학생 본인이 확인합니다. 위험한 경우는 나중에 관리자가 검토합니다.
- 웹캠 관찰(Phase 3A–3D)은 별개이며 키오스크 출석에 쓰이지 않습니다.

**시범 운영 정책입니다.** 지금은 학생이 인식된 이름을 확인하는 순간 키오스크 출석이 확정되고, 이후에 교사가 다시 확정하지 않습니다. 많은 데이터로 사용자 테스트를 한 뒤, 그 결과에 따라 이대로 확정할지, 교사가 키오스크 기록을 다시 확정하게 할지 정합니다([결정이 필요한 것](#결정이-필요한-것) 참고).

## 범위와 한계

- **인식기 설정**: Phase 1 인식기와 설정을 그대로 씁니다. `CV_SERVICE_URL`, `CV_SERVICE_KEY`, `CV_ENCRYPTION_KEY`는 [Phase 1 가이드](phase1-photo-attendance.ko.md)를 보세요. 인식이 꺼져 있으면 키오스크를 시작할 수 없습니다.
- **키오스크 하나에 세션 하나**: 세션에 수업이 지정되어 있어야 하고, 활성·승인 학생이 30명 이하여야 합니다. 그중 한 명 이상은 얼굴 동의가 유효하고 얼굴 등록을 마친 학생이어야 합니다([Phase 2A](phase2a-student-checkin.ko.md)).
- **후보가 나오는 방식**: 후보는 그 수업의 얼굴 준비 완료 학생 중에서만 나옵니다.
  - 가장 높은 유사도가 `CV_MATCH_THRESHOLD`(기본 `0.5`, 보정하지 않은 시범값)보다 낮으면 이름을 보여주지 않습니다.
  - 기준을 넘으면 2·3순위 점수가 낮더라도 상위 3개를 보여줍니다. 닮은 사람 이름이 함께 나올 수 있습니다. 이름 3개가 나오려면 그 수업에 얼굴 준비 완료 학생이 3명 이상 있어야 합니다.
- **본인 확인의 한계**: 키오스크는 이름을 누른 사람이 인식된 사람과 같은지 확인하지 않습니다. 1순위 이름을 고르면 검토 항목이 생기지 않으므로, 다른 사람이 1순위로 나온 이름을 골라도 표시되지 않습니다.
- **위조 판별 없음**: 실제 사람인지 확인하는 기능이 없어서 인쇄한 사진도 인식될 수 있습니다.
- **결석·행동 판단 아님**: 얼굴 없음, "I'm not listed", 시간 초과, 취소된 스캔은 결석이 아닙니다. 키오스크 사진은 집중도나 행동의 증거가 아닙니다.
- **배포 승인 아님**: 실제로 도입하려면 법률, 기관 정책, 유효한 동의, 모델 적합성, 보안, 백업 보관 정책을 먼저 검토해야 합니다.

## 동작 순서

1. 교사가 날짜(와 캠퍼스)를 골라 키오스크를 시작할 수 있는 세션을 확인합니다.
2. 세션, 캠퍼스, 위치, 지각 기준을 정하고 기기 확인란을 체크해 시작합니다. 같은 트랜잭션에서 교사 로그인이 취소되고, 키오스크 전용 쿠키가 교사 쿠키를 대신합니다.
3. 키오스크 브라우저가 기기 안에서 얼굴 위치만 보고, 한 사람이 2초 동안 서 있으면 사진 한 장을 업로드합니다.
4. 백엔드가 시도를 예약하고 암호화한 사진을 저장합니다. 그다음 DB 잠금을 잡지 않은 채, 그 수업의 얼굴 준비 완료 템플릿으로 인식기를 호출합니다.
5. 후보 목록을 암호화해 저장하고, 키오스크에는 짧은 이름만 보냅니다. 사진은 보내지 않습니다.
6. 학생이 이름을 확인하거나 취소합니다. 확인하면 출석이 `PRESENT` 또는 `LATE`(출처 `KIOSK`)로 기록되고, 필요하면 검토 항목이 생깁니다.

## 교사: 키오스크 시작과 종료

교사와 관리자는 콘솔 메뉴의 **Entrance Kiosk**에서 시작합니다.

1. 캠퍼스와 세션을 고릅니다. 키오스크를 쓸 수 없는 세션에는 이유가 표시됩니다.

   | 이유 | 뜻 |
   | --- | --- |
   | `CANCELLED` | 취소된 세션 |
   | `WINDOW_CLOSED` | 이미 끝났거나, 완료 처리됐거나, 지난 날짜인 세션 |
   | `TOO_EARLY` | 수업 시작 2시간 전보다 이른 시각 |
   | `NO_CLASS` | 수업이 지정되지 않은 세션 |
   | `ROSTER_TOO_LARGE` | 대상 학생 30명 초과 |
   | `RECOGNITION_DISABLED` | 인식기 설정 없음 |
   | `NO_FACE_READY_STUDENTS` | 얼굴 동의와 등록을 모두 마친 학생 없음 |

2. 위치 이름을 2~80자로 입력합니다(예: "Main entrance").
3. 필요하면 **Mark Late after**를 수업 시작 후 0~60분으로 정합니다. 그 이후에 찍힌 체크인은 `LATE`로 기록됩니다. 정하지 않으면 모두 `PRESENT`입니다.
4. 기기 확인란을 체크하고 **Start kiosk on this device**를 누릅니다. 키오스크 캠퍼스는 강의실 캠퍼스와 같아야 합니다.

세션 접근 권한은 공통 규칙을 따릅니다. 관리자, 그 수업의 담당 교사, 수업이 없는 세션의 담당 교사만 시작할 수 있습니다.

**키오스크를 시작하면 이 브라우저는 로그아웃됩니다.**
- 같은 트랜잭션에서 교사 로그인이 취소되고, 키오스크 전용 쿠키(host-only, `HttpOnly`, `SameSite=Strict`)가 그 자리를 대신합니다. 그래서 그 브라우저 프로필의 모든 탭이 키오스크가 됩니다.
- 이유: 로그인 쿠키는 브라우저당 하나라서 교사 세션과 키오스크가 한 프로필에 같이 있을 수 없습니다. 또 지켜보는 사람이 없는 입구 기기에 교사 세션을 남겨 두면 교사 화면이 노출됩니다.
- 같은 컴퓨터에서 교사 작업을 계속하려면 키오스크를 다른 브라우저 프로필이나 시크릿 창에서 열거나, 태블릿 같은 별도 기기를 쓰세요.

**키오스크가 끝나는 경우**

| 종료 이유 | 언제 |
| --- | --- |
| `EXPIRED` | 수업 종료 10분 후와 시작 후 12시간 중 이른 시각 |
| `DEVICE_EXIT` | 기기에서 **Staff** → **Exit kiosk** |
| `STAFF_ENDED` | 교사가 시작 화면의 **Kiosk activity**에서 종료 |
| `ACCESS_LOST` | 키오스크를 시작한 교사가 그 수업 권한을 잃음 |

키오스크가 끝나면 키오스크 인증이 바로 취소됩니다. 기기에서 나갈 때 비밀번호를 묻지 않는 이유는, 나가기가 키오스크를 끝내고 브라우저를 로그아웃시키는 일만 하기 때문입니다. 그 브라우저를 다시 쓰려면 교사가 다시 로그인해야 합니다. 키오스크 쿠키로는 교사 화면을 열 수 없습니다.

시작 화면의 **Kiosk activity**에는 선택한 세션의 키오스크 목록(위치, 시작한 사람, 시작·만료 시각, 종료 이유, 확인 수)과 페이지로 나뉜 체크인 기록이 나옵니다.

## 학생: 키오스크 사용 흐름

- **체크인 시간**: 수업 시작 15분 전부터 수업 종료까지 열립니다. 예정 또는 진행 중인 세션만 해당됩니다. 열리기 전에는 대기 화면이, 끝난 뒤에는 "Check-in has closed"가 나옵니다.
- **스캔 방식**:
  - 기기 안의 얼굴 감지(Phase 3A MediaPipe worker)는 촬영 시점만 정하고, 직접 업로드하지 않습니다.
  - 얼굴 하나가 2초 동안 화면에 있으면 한 번 촬영합니다. 얼굴 너비가 화면 너비의 16% 이상이어야 합니다. **Check in now**를 누르면 바로 촬영합니다.
  - 결과가 나온 뒤 다음 스캔은 카메라에 아무도 없는 상태가 1초 이어지거나 6초가 지나야 시작됩니다.
  - 업로드는 좌우 반전하지 않은 JPEG 한 장이고, 긴 변 960px, 2MB 이하입니다.
- **스캔 결과**

  | 결과 | 키오스크 표시 |
  | --- | --- |
  | `NO_FACE`, `MULTIPLE_FACES`, `LOW_QUALITY` | 안내와 함께 다시 시도 |
  | `NO_CANDIDATE` | 한 번 더 시도하고, 연속 두 번째면 교사에게 문의하도록 안내 |
  | 후보 있음 | **Is this you?** 화면에 이름 최대 3개 |

- **이름 표시 방식**: 이름은 짧게 보여줍니다(이름 + 성의 첫 글자). 짧은 이름이 겹치면 전체 이름을 쓰고, 그래도 겹치면 학번 끝 세 자리를 붙입니다. 사진은 보여주지 않습니다.
- **선택**: 학생은 이름을 누르고 **Confirm attendance**를 누르거나, **I'm not listed**를 누릅니다. 기기에서는 30초 뒤 선택이 닫히고, 서버는 답이 없는 스캔을 120초 뒤 만료합니다.
- **확인 결과**

  | 결과 | 뜻 |
  | --- | --- |
  | `CONFIRMED` | `PRESENT` 또는 `LATE`로 기록 |
  | `ALREADY_RECORDED` | 이미 있는 `PRESENT`/`LATE` 기록을 그대로 둠 |
  | `ATTENDANCE_LOCKED` | 교사가 이미 `ABSENT`로 처리해서 덮어쓰지 않음 |
  | `NOT_ENROLLED` | 활성·승인 수강 등록이 없음, 검토 항목 생성 |
  | `CANDIDATES_STALE` | 스캔 중 동의나 등록 상태가 바뀜, 다시 스캔 |
  | `KIOSK_SESSION_CLOSED`, `ATTEMPT_EXPIRED` | 닫혔거나 시간 초과, 기록 없음 |

- **확인했을 때 기록되는 내용**: 상태 `PRESENT` 또는 `LATE`, 출처 `KIOSK`, 체크인 시각(= 촬영 시각)을 저장하고 결석 사유는 지웁니다. 출석 검토 기록에 `KIOSK_SELF_CONFIRMED` 항목도 추가합니다.

## 관리자 검토

관리자 메뉴의 **Kiosk Reviews**에 열린 항목 수가 배지로 표시됩니다. 항목 종류는 두 가지입니다.

- `CANDIDATE_SELECTION_MISMATCH`: 학생이 인식기의 원래 1순위가 아닌 이름(2·3순위)을 골랐고, 출석이 확정됐거나 이미 기록되어 있던 경우
- `NOT_ENROLLED_ATTEMPT`: 고른 학생에게 활성·승인 수강 등록이 없는 경우

각 항목에는 고른 학생, 1순위 후보, 수업, 캠퍼스, 위치, 시각, 결과, 그리고 만료 전까지의 촬영 사진이 나옵니다. **Verified correct**, **Attendance corrected**, **No action** 중 하나로 처리하고 500자 이하 메모를 남길 수 있습니다. 처리해도 출석은 바뀌지 않으니, 고칠 것이 있으면 세션 출석부를 먼저 수정하세요. 이미 처리한 항목을 다른 결과로 다시 처리하면 `409 REVIEW_ALREADY_RESOLVED`가 반환됩니다.

## 데이터, 개인정보, 보관

- **기기 화면의 개인정보 안내**:
  - 키오스크 화면에는 뉴질랜드 생체정보 처리 규약(Biometric Processing Privacy Code 2025) rule 3가 요구하는 최소 안내가 항상 보입니다. 얼굴 인식을 쓴다는 사실, 사용 목적, 카메라를 쓰지 않는 방법, 자세한 안내를 보는 곳입니다.
  - **Privacy** 버튼을 누르면 전체 안내가 열립니다. 운영 기관과 시범 운영, 수집하는 정보와 이유, 볼 수 있는 사람, 보관 기간, 열람·정정 권리가 들어 있습니다.
  - 안내가 열려 있는 동안에는 자동 촬영을 멈추고, 60초가 지나면 안내가 저절로 닫힙니다.
  - 휴대폰처럼 세로가 짧은 화면에서는 이름을 고르는 동안에만 안내가 제목 한 줄로 줄어듭니다. 이름과 확인 버튼이 화면 안에 들어오게 하기 위해서입니다. 태블릿, 데스크톱, 결과 화면에서는 항상 전체 안내가 보입니다.
  - 문구와 운영 기관 정보는 `features/entrance-kiosk/privacyNotice.ts`에 있습니다.
  - 이 안내는 내부 테스트용입니다. [참가자 테스트 전에 할 일](#참가자-테스트-전에-할-일)을 마치기 전에는 참가자 테스트에 쓸 수 있는 완성본이 아닙니다.
- **촬영 사진**: 학생이 이름을 고르는 동안 시도별로 묶인 키로 암호화해 두었다가, 시도가 끝나면 바로 지웁니다.
- **증거 사진**: `CONFIRMED`, `BLOCKED_NOT_ENROLLED`, 그리고 원래 1순위가 아닌 이름을 골라(`selectedRank` > 1) `ALREADY_RECORDED`가 된 경우에만 암호화해 30일 동안 보관합니다. 관리자만 받을 수 있고, 만료되면 `410 EVIDENCE_EXPIRED`가 반환됩니다.
  - 순위는 화면에 보인 순서가 아니라 인식기가 처음 매긴 순위입니다. 인식하는 동안 1순위 후보가 삭제되면 원래 2순위가 화면 맨 위에 나오지만, 여전히 2순위로 셉니다.
- **후보 목록**: 시도가 열려 있는 동안만 암호화해 두고, 시도가 끝나면 지웁니다.
- **응답과 로그**: 키오스크 응답에는 사진이나 얼굴 템플릿이 들어가지 않고, 템플릿은 인식기에만 전달됩니다. 키오스크 응답, 촬영 사진, 증거 사진은 로그에 찍힐 때 가려집니다.
- **시도 기록에 남는 것**: 상태, 후보 수, 1순위 후보 ID, 고른 학생·순위·표시 이름, 출석 상태, 품질 사유, 캠퍼스, 위치, 시각입니다.
- **자동 정리**: 백엔드가 실행 중이면 10분마다 답이 없는 스캔을 만료하고, 30일이 지난 증거 사진을 지우고, 만료된 키오스크를 종료합니다. 백업은 별도 보관 정책을 따릅니다.
- **학생 삭제**:
  - 고른 학생을 삭제하면 그 학생의 시도, 증거 사진, 검토 항목도 함께 삭제됩니다.
  - 1순위 후보였던 학생을 삭제하면 시도와 증거 사진은 그대로 두고 1순위 연결만 비웁니다(V10).

## 백엔드 계약

오류는 `code` 필드가 있는 `application/problem+json`으로 보냅니다. `429`에는 모두 `Retry-After: 2`가 붙습니다.

| 경로 | 호출자 | 요청 → 응답 |
| --- | --- | --- |
| GET `/api/kiosk/launch-options?date=&campusId=` | 교사 | 캠퍼스 목록, 그 날짜의 접근 가능한 세션(`launchable`, `blockedReason`, `rosterSize`, `faceReadyCount`), 캠퍼스별 최근 위치 최대 10개 |
| POST `/api/kiosk/sessions` | 교사 | `{sessionId, campusId, locationLabel, lateAfterMinutes, deviceConfirmed: true}` → 201과 키오스크 쿠키, 교사 로그인 취소 |
| GET `/api/kiosk/sessions?sessionId=` | 교사 | 세션의 키오스크 목록과 확인 수 |
| POST `/api/kiosk/sessions/{id}/end` | 교사 | 204, 키오스크 종료(`STAFF_ENDED`) |
| GET `/api/kiosk/attempts?sessionId=&page=&size=` | 교사 | 체크인 기록, 최신순, size 1~100 |
| GET `/api/kiosk/device` | 키오스크 | 수업, 캠퍼스, 위치, 체크인 시간 상태, 서버 시각, `captureCooldownMs` 2000, `attemptTtlSeconds` 120, `maxImageBytes` |
| POST `/api/kiosk/device/captures` | 키오스크 | multipart `image`(JPEG·PNG 서명 확인, 2MB 이하)와 `Idempotency-Key` UUID 헤더 → 새 요청 201, 재요청 200 |
| POST `/api/kiosk/device/attempts/{id}/confirm` | 키오스크 | `{candidateId}` → `{attemptId, result, attendanceStatus, displayName, processedAt, replayed}` |
| POST `/api/kiosk/device/attempts/{id}/cancel` | 키오스크 | `{reason: "NOT_LISTED" 또는 "TIMEOUT"}` → 204 |
| GET `/api/admin/kiosk-reviews?state=OPEN\|RESOLVED\|ALL&page=&size=` | 관리자 | 검토 항목 |
| GET `/api/admin/kiosk-reviews/summary` | 관리자 | `{open}` |
| GET `/api/admin/kiosk-reviews/{id}/evidence` | 관리자 | 복호화한 사진 또는 410 |
| POST `/api/admin/kiosk-reviews/{id}/resolve` | 관리자 | `{resolution, note}` |

**캡처**
- **응답**: `attemptId`, `outcome`, `state`, `qualityReasons`, `candidates`, `capturedAt`, `expiresAt`. 후보 하나는 `{candidateId, rank, displayName, photo: null}`입니다.
- **후보 ID**: `candidateId`는 `"c"` + 인식기가 매긴 원래 순위입니다. 인식하는 동안 순위에 있던 학생이 삭제되면 번호가 빌 수 있습니다(예: `c1` 없이 `c2`, `c3`). 클라이언트는 ID를 해석하지 말고 그대로 써야 합니다.
- **같은 키로 다시 보낼 때**:
  - 사진이 같아야 합니다. 다르면 `409 IDEMPOTENCY_KEY_REUSED`입니다.
  - `NO_FACE`, `MULTIPLE_FACES`, `LOW_QUALITY`, `NO_CANDIDATE`와 아직 열린 시도는 처음 응답을 그대로 돌려줍니다.
  - 이미 끝난 시도는 오류를 돌려줍니다. 만료는 `410 ATTEMPT_EXPIRED`, 세션 종료는 `409 KIOSK_SESSION_CLOSED`, 그 밖의 종료 상태는 `409 ATTEMPT_FINALIZED`입니다.
  - 아직 처리 중이면 `429 RECOGNIZER_BUSY`입니다.
- **그 밖의 오류**

  | 코드 | 상태 | 언제 |
  | --- | --- | --- |
  | `KIOSK_WINDOW_NOT_OPEN` | 409 | 체크인 시간 전 |
  | `NO_FACE_READY_STUDENTS` | 409 | 얼굴 준비 완료 학생 없음 |
  | `CAPTURE_RATE_LIMITED` | 429 | 직전 촬영 후 2초가 지나지 않음 |
  | `RECOGNIZER_BUSY` | 429 | 인식기나 이 기기가 처리 중 |
  | `RECOGNITION_UNAVAILABLE` | 503 | 인식기를 쓸 수 없음 |
  | `RECOGNIZER_INVALID_RESPONSE` | 502 | 인식기 응답이 잘못됨 |
  | `INVALID_IMAGE` | 400 | JPEG·PNG가 아님 |
  | `IMAGE_TOO_LARGE` | 413 | 2MB 초과 |

- **이전 시도 대체**: 같은 기기에서 새로 촬영하면, 그 기기에 열려 있던 이전 시도는 `SUPERSEDED`로 끝납니다.

**확인**
- **다시 보낼 때**: 같은 후보를 다시 보내면 처음 결과를 `replayed: true`로 돌려줍니다. 이미 끝난 시도에 다른 후보를 보내면 `409 ATTEMPT_FINALIZED`입니다.
- **오류**: `ATTEMPT_EXPIRED`(410), `KIOSK_SESSION_CLOSED`(409), `NOT_ENROLLED`(403), `CANDIDATES_STALE`(409), `ATTENDANCE_LOCKED`(409), `INVALID_CANDIDATE`(400).

**DB**
- **V9**: 로그인 역할과 출석 출처에 `KIOSK`를 추가하고, `kiosk_sessions`, `kiosk_attempts`, `kiosk_evidence`, `kiosk_review_items` 테이블을 만듭니다.
- **V10**: 1순위 후보 학생이 삭제되면 시도를 지우지 않고 `top_student_id`만 비웁니다. 캠퍼스를 삭제하기 전 보관 기록을 확인할 수 있도록 캠퍼스 인덱스도 추가합니다.
- **적용 방법**: 백엔드가 시작될 때 Flyway가 두 마이그레이션을 자동으로 적용합니다. SQL을 직접 실행하지 마세요.

## 로컬 테스트

1. 저장소 루트에서 스택을 실행합니다.

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\data\local-dev\start.ps1
   powershell -ExecutionPolicy Bypass -File .\data\local-dev\stop.ps1
   ```

   `http://127.0.0.1:5173`을 엽니다. 백엔드를 바꿨다면 재시작하세요.
2. 오늘 날짜에 수업이 지정된 세션(학생 30명 이하)을 준비합니다. 한 명 이상은 얼굴 동의와 얼굴 등록을 마쳐야 합니다. 후보 3개를 보려면 얼굴 준비 완료 학생이 3명 필요합니다.
3. 키오스크를 시작하면 그 브라우저가 로그아웃되므로, 키오스크는 다른 브라우저 프로필, 시크릿 창 또는 다른 기기에서 여세요.
4. 확인할 경우:
   - 한 사람: 스캔 → 올바른 이름 → `PRESENT`. 지각 기준이 지난 뒤 다시 해서 `LATE`도 확인합니다.
   - **I'm not listed**를 누르거나 선택 시간을 넘김: 아무것도 기록되지 않습니다.
   - 두 사람이 같이 비침: "One person at a time"이 나옵니다.
   - 얼굴 등록이 없는 사람이 연속 두 번 스캔: 교사에게 문의하라는 안내가 나옵니다.
   - 2순위 이름 선택: 관리자 검토 항목이 생깁니다.
   - 교사가 이미 결석 처리한 학생: 출석을 덮어쓰지 않습니다.
   - 다른 브라우저의 **Kiosk activity**에서 종료하기, 기기에서 **Exit kiosk** 누르기.
5. 관리자로 **Kiosk Reviews**를 열어 사진을 확인하고 항목을 처리합니다.

## 알려진 한계

- **인식 중 백엔드가 멈추면 잠시 막힘**: 사진을 인식하는 도중 백엔드가 멈추면, 예약된 시도가 만료될 때까지 최대 2분 동안 그 기기의 다음 촬영이 `RECOGNIZER_BUSY`를 받습니다.
- **브라우저 프로필당 교사 세션 하나**: 키오스크를 시작하면 그 프로필은 로그아웃됩니다.
- **약한 추가 후보**: 매칭 기준값을 보정하지 않았고, 2·3순위 후보는 유사도가 낮을 수 있습니다.
- **위조 판별 없음**
- **미리보기에 다 보이지 않음**: 미리보기는 상자를 꽉 채우도록 화면을 잘라 보여주지만(`object-fit: cover`), 업로드는 카메라 전체 화면입니다. 그래서 미리보기에 보이지 않는 사람 때문에 `MULTIPLE_FACES`가 나오거나 그 사람이 인식될 수 있습니다.
- **자동 정리는 백엔드가 켜져 있을 때만**: 보관 기간 정리는 백엔드가 실행 중일 때만 돌아갑니다.

## 결정이 필요한 것

- **키오스크 기록의 교사 확정 여부**: 시범 운영에서는 학생이 확인하면 키오스크 출석이 바로 확정됩니다. 대규모 사용자 테스트 후 이대로 둘지, 교사가 다시 확정해야 출석으로 인정할지 정합니다. 판단 근거로 쓸 수 있는 테스트 데이터는 1순위 후보가 틀린 비율, 학생이 1순위가 아닌 이름을 고른 비율, 관리자가 검토 항목을 **Attendance corrected**로 처리한 비율입니다.
- **미리보기와 인식 범위**: 업로드를 미리보기에 보이는 범위로 자를지, 미리보기에 카메라 전체 화면을 보여줄지 정해야 합니다.
- **1순위 후보가 삭제된 경우의 증거 사진**: 지금은 시도와 사진을 30일 만료까지 보관하고 1순위 연결만 비웁니다. 이대로 유지하는 것을 권장하며, 확정이 필요합니다.
